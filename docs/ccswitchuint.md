# ccSwitchUint 多用户使用说明

## 界面与权限

登录后直接进入 CC Switch Web 工作台。全局侧栏提供“模型与接入”“统一供应商”“使用统计”“账号”“额度分配”“配额与账本”“用户与额度”和“个人账号”；Claude、Codex 等应用切换保留在顶栏。侧栏不再重复列出各模型供应商、设备密钥、Skill、MCP、提示词、会话、应用和设置，顶栏不再提供设置与项目切换入口。

服务器监听与出站代理继续由服务端配置管理，Web 导航不再暴露设置页。供应商的原编辑、删除和加入/退出按钮仅提供者可操作；服务端独立检查权限，不依赖界面是否禁用。供应商页按“我的供应商”和“共享给我的供应商”分组，共享供应商显示来源并作为只读配置使用。

“使用统计”沿用原有图表和请求表，可选择“我的调用”“我提供的资源”，管理员还可以查看“全平台”；“配额与账本”补充设备、用户分组和待核算记录。历史单用户日志留在数据库中，不与新用户账本混算。

## 登录与迁移

- 首次启动创建管理员 `admin`。密码优先读取 `CC_SWITCH_ADMIN_PASSWORD`，其次采用迁移前的 `CC_SWITCH_WEB_ACCESS_KEY`；未配置时随机生成。初始凭据写入数据目录 `ccswitchuint-admin-initial.txt`，Unix 权限为 0600。
- 浏览器通过 HttpOnly 会话 Cookie 记住登录，默认 7 天；修改密码撤销全部网页会话。
- 默认开放注册，新用户具有每月 1000 次请求、1,000,000 token 的平台额度，30 RPM、2 个并发请求。管理员可以在平台管理中关闭注册、修改用户额度和限流、停用用户或重置密码。
- 现有供应商、聚合 key 和官方账号迁移到管理员。保留旧密钥，并绑定到 `legacy-client`，只用于兼容客户端调用和模型更新；旧密钥不能进入网页管理接口。该身份仅兼容管理员共享资源。
- 历史单用户统计保留在原始日志表，供管理员运维查询。缺少可信用户身份的旧记录不会被虚构分配给新用户；新的用户统计从多用户网关启用时开始。

## 供应商与共享

原供应商页面通过“添加”和“编辑”配置 Codex/Claude 资源，继续使用原表单、预设、TOML/JSON 编辑器。供应商配置只保存在服务端，不投影到 moss 本机客户端文件。页面将自有资源和共享资源分组：自有资源由所有者维护；共享资源标明提供者，配置只读。

资源初始不加入聚合。所有者配置完成后选择“加入聚合”；移除和加入都由所有者操作。管理员可以独立停用资源，但不能代替他人操作发布开关。

“额度分配”是独立页面，不再与供应商编辑混在一起。页面先选择一个自有供应商，再使用“指定用户”或“分享口令”模式：

- 指定用户模式设置共享范围（所有已注册用户、仅指定用户或仅自己）、每人的默认额度、所有共享用户的合计预算、共享模型范围和账期。单独分配覆盖默认额度，支持禁用、独立额度、模型范围和到期时间。仅自己模式会覆盖既有共享授权。
- 分享口令模式生成限时分享链接。每条口令可设置每位领取者获得的额度、模型范围、到期时间和最多领取次数；默认最多领取 1 次。链接使用先到先得规则，领取成功后写入该用户的单独授权。
- 分享令牌只以 SHA-256 哈希保存在数据库，明文和完整链接仅在创建时返回。领取在 SQLite 立即事务中完成，并发请求只有一个能占用剩余名额；禁止自领、重复领取、过期领取和领完领取。
- 撤销分享口令只阻止后续领取，不收回已经生成的个人授权。分享额度仍受供应商共享池预算、平台额度和上游实际限制约束。

额度支持请求次数、token、点数，周期为每天、每月或累计，账期按 UTC。

额度留空表示不限，0 表示没有额度。所有者免受自己资源的分配额度限制，仍记录实际用量，并受个人平台额度、服务并发与上游实际限制。点数是估算成本：1,000,000 点对应 $1；官方订阅的估算不代表逐次实际账单。

普通用户提交的上游只能访问解析并固定后的公网 IP，阻止私网和云元数据访问及 DNS 重绑定。HTTP 上游代理使用已校验 IP 建立 CONNECT；普通用户资源的 SOCKS 出站暂不开放。管理员管理的资源和官方固定上游继续沿用现有网络配置。获取模型限制响应大小、超时和重定向。

## 个人模型与远程机器接入

1. 在“模型与接入”勾选获授权的 Codex 模型并保存；模型选择默认折叠。
2. 在同一页面为每台机器创建设备密钥，并复制生成的完整接入命令。页面也提供聚合模型同步命令和模型目录下载入口。
3. 在对应远程机器执行命令，安装器会备份并原子写入模型目录和 Codex 配置，写入统一代理地址及该设备密钥，并尝试重启 app-server。
4. 以后修改模型选择，重复执行保存的命令同步即可。密钥明文只在创建时显示，遗失时创建新密钥并撤销旧密钥。

`CC_SWITCH_CONFIGURE_ROUTE=1` 表示写入个人路由；不设置时沿用原有脚本语义，仅更新模型目录及启动模型。启动模型是客户端偏好，服务器没有默认供应商，也不对裸模型名执行隐式回退。修改客户端目录无法绕过服务端授权或额度。

## 官方账号池

在原“授权中心”的 ChatGPT 区域发起设备授权流程，登录后在“供应商”创建绑定到自己账号的官方资源，然后设置共享与入池规则。同一真实账号只绑定一个所有者和一个有效资源，防止重复计量和刷新竞争。

- `ccs-供应商key/模型` 明确选择某个资源。
- `ccs-official/模型` 选择官方共享池，优先本人可用资源，再在其他获授权资源间轮询。
- 候选必须已发布、获得当前调用者授权、支持模型、具有分配额度，并且登录有效、未处于冷却状态。
- 明确的 401/403/429 拒绝可在尚未输出、无账号绑定会话时换账号；Refresh Token 失效标记为需要重新登录，403 按模型排除，429 记录冷却。
- `previous_response_id` 按调用者记录归属和实际账号，不能引用他人的响应；相关请求保持账号亲和性。无归属的 `item_reference` 不接受。
- 已输出内容、执行状态未知或需要保持账号状态的请求，不进行透明重放。官方精确剩余 token 通常不可得，账号健康与上游订阅窗口只是调度依据。

## 用量与额度结算

统计页面分“我的消费”“我提供的资源”和管理员“平台全部”，支持日期、模型、供应商、设备、使用者分组，以及分页明细、请求尝试记录和 JSON 统计导出。请求表提供独立用户列和用户名筛选。所有者查看他人消费时只看到计量元数据，不提供对话内容或上游密钥。

个人页以用户用量为主，集中展示平台额度、每周期请求/token/点数和进行中预留，并分组列出自有供应商与共享供应商余额。自有供应商显示共享池预算和使用量；共享供应商显示个人授权、个人已用、共享池背景和剩余可用额度。

每个网关请求持久化调用者、设备、提供者、实际账号、模型、用量、定价快照和结算状态。代理诊断日志、客户端会话日志与网关额度账本分开，本机会话导入不扣共享额度。一个请求在消费者、提供者视角出现，不会在平台重复计数。

网关先在数据库事务中预留预算，再调用上游，返回后按实际 usage 幂等结算。重试关联同一个逻辑请求，失败候选释放资源预留；全局保护为最多 16 个正在处理请求头的请求和 32 个进行中逻辑请求，另受用户自己的 RPM/并发限制。

请求次数与并发限制可确定执行。token/点数预留基于请求大小与输出上限的估算，并非逐 token 的绝对上限；实际用量可能超过估算。未知 usage、中断和重启前未完成的请求保留为“待核算”，释放并发但不自动返还预算。管理员可以核对 usage 后通过对账接口结算，或在界面明确释放预留，操作留审计记录。日志清理不会返还额度。

## 部署与运维

沿用原 Rust 服务与前端构建流程。新增可配置环境变量：

```text
CC_SWITCH_ADMIN_PASSWORD       仅首次初始化管理员时使用
CC_SWITCH_PUBLIC_URL           公开网页地址，供接入命令和来源校验使用
CC_SWITCH_PUBLIC_PROXY_URL     公开模型代理地址，通常以 /v1 结尾
CC_SWITCH_WEB_ACCESS_KEY       迁移前客户端兼容密钥
```

公开 URL 也可在平台管理中设置，数据库设置优先。HTTPS 入口启用 Secure 会话 Cookie；服务端不自动申请证书，TLS 可由反向代理终止，FRP 继续转发对应端口。服务器目录、代理进程、工具安装、MCP/Skills 文件操作和整库导出保留原界面，并由管理员权限控制。在线整库导入、恢复和 WebDAV 覆盖被阻止，避免回退额度账本或密钥撤销记录。

数据库版本升级到 18，新增 `hub_share_codes` 和 `hub_share_claims`。从 17 升级会保留原供应商、授权、用户、设备密钥和额度账本；回滚到 17 及更早二进制时必须同时恢复对应的升级前数据库，避免新二进制已经写入的分享记录和授权被错误解释。停止服务后先另存当前数据库/账号状态，再恢复旧二进制与数据库，最后启动并核对服务。OAuth 文件结构沿用原实现；若刷新令牌已经轮换，不应无故覆盖为更旧的账号文件。
